# 📡 V2Ray Config Sender — ارسال زمان‌بندی‌شده کانفیگ به کانال‌های تلگرام

یک پروژه‌ی کامل روی **GitHub Actions** که فایل `working.txt` (پر از کانفیگ V2Ray) را می‌خواند،
تبلیغات و یوزرنیم‌های تزریق‌شده را پاک می‌کند، نام کانال مقصد را روی هر کانفیگ می‌گذارد،
کانفیگ‌ها را بین چند کانال تقسیم می‌کند و در طول ۲۴ ساعت به‌صورت زمان‌بندی‌شده می‌فرستد.

با **Telethon** و `api_id` / `api_hash` / `session string` کار می‌کند — بدون نیاز به بات‌توکن.

## ۱. این پروژه چه می‌کند

هر بار که ورک‌فلو اجرا می‌شود (پیش‌فرض: هر ۱۵ دقیقه) این مراحل طی می‌شود:

```
working.txt  (۱۷۰ کانفیگ خام با تبلیغات)
      │
      ├─ ۱. پارس و اعتبارسنجی      ← کانفیگ خراب/ناقص حذف می‌شود
      ├─ ۲. تمیزکاری تبلیغات        ← @username ها، «Join Telegram»، توکن‌های تکراری
      ├─ ۳. اثر انگشت (fingerprint) ← شناسه معنایی بدون توجه به remark
      ├─ ۴. فیلتر کش                ← هر چیزی که قبلاً رفته حذف می‌شود
      ├─ ۵. تقسیم بین کانال‌ها       ← round-robin با سهمیه‌ی هر کانال
      ├─ ۶. دسته‌بندی و زمان‌بندی     ← ۱۰ تایی، پخش‌شده در ۲۴ ساعت
      │
      ▼
state/queue.json   ← نقشه‌ی زمانی (چه چیزی، کِی، کجا)
      │
      ▼
هر ران: فقط دسته‌هایی که وقتشان رسیده ارسال می‌شود
      │
      ▼
state/cache.json   ← اثر انگشت‌های ارسال‌شده، کامیت می‌شود در ریپو
```

مهم‌ترین ویژگی‌ها:

- **بدون تکرار، هرگز** — کانفیگی که یک‌بار به هر کانالی رفته، دیگر به هیچ کانالی نمی‌رود.
- **مقاوم در برابر قطع شدن** — وضعیت بعد از هر دسته ذخیره می‌شود؛ کرش وسط ران باعث ارسال دوباره یا گم شدن کار نمی‌شود.
- **همه‌ی اعداد آپشنال** — تعداد کانال، سهمیه هر کانال، اندازه دسته، طول بازه، همه در `config.json` قابل تغییرند.
- **قابل کپی با یک تاچ** — همه‌ی کانفیگ‌های یک پیام داخل یک `<pre>` قرار می‌گیرند.

## ۲. راه‌اندازی در ۶ قدم

```bash
# ۱. ریپو را کلون کنید
git clone https://github.com/<user>/v2ray-config-sender.git
cd v2ray-config-sender

# ۲. api_id و api_hash را از my.telegram.org بگیرید  (بخش ۳)

# ۳. session string بسازید
pip install telethon
python tools/gen_session.py

# ۴. سه سکرت را در گیت‌هاب ثبت کنید  (بخش ۵)

# ۵. نام کانال‌ها را در config.json بگذارید
#    "channels": [{"username": "@myChannel", "daily_quota": 100}, ...]

# ۶. اکانتِ session را در هر سه کانال ادمین کنید (با دسترسی Post Messages)
```

بعد از پوش کردن، ورک‌فلو خودش هر ۱۵ دقیقه اجرا می‌شود. برای شروع فوری:
تب **Actions** → ورک‌فلو **Send configs** → **Run workflow**.

## ۳. گرفتن api_id و api_hash

1. به [my.telegram.org](https://my.telegram.org) بروید و با شماره‌ی تلگرام خود وارد شوید.
2. **API development tools** را باز کنید.
3. فرم را پر کنید (نام اپ هر چیزی می‌تواند باشد، مثلاً `config-sender`؛ پلتفرم: Other).
4. مقادیر **App api_id** (یک عدد) و **App api_hash** (۳۲ کاراکتر هگز) را کپی کنید.

> این دو مقدار به اکانت شما گره خورده‌اند و قابل تغییر نیستند. آن‌ها را جای امنی نگه دارید.

## ۴. ساخت Session String

`session string` یعنی «یک اکانت لاگین‌شده به‌شکل یک رشته متن». چون GitHub Actions
نمی‌تواند کد تأیید تلگرام را وارد کند، این رشته را **یک‌بار روی کامپیوتر خودتان** می‌سازید:

```bash
pip install telethon
python tools/gen_session.py
```

اسکریپت به‌ترتیب می‌پرسد: `api_id` ← `api_hash` ← شماره تلفن ← کد تأییدی که تلگرام
می‌فرستد (و اگر رمز دومرحله‌ای دارید، آن را هم). در پایان یک رشته‌ی بلند چاپ می‌شود:

```
=== TELEGRAM_SESSION (copy the single line below) ===

1BVtsOMAB...بسیار طولانی...cE9k=

=== keep this secret — it grants full access to the account ===
```

کل آن یک خط را کپی کنید.

> ⚠️ این رشته **معادل رمز اکانت** شماست. هرگز آن را کامیت نکنید، در چت نفرستید و در
> ایشوها پیست نکنید. اگر جایی لو رفت، در تلگرام به
> **Settings → Devices → Terminate all other sessions** بروید و یک رشته‌ی جدید بسازید.

## ۵. ثبت Secrets در گیت‌هاب

مسیر: **Settings → Secrets and variables → Actions → New repository secret**

| نام سکرت | مقدار | اجباری؟ |
|---|---|---|
| `TELEGRAM_API_ID` | عدد api_id | ✅ بله |
| `TELEGRAM_API_HASH` | رشته api_hash | ✅ بله |
| `TELEGRAM_SESSION` | خروجی `gen_session.py` | ✅ بله |
| `CHANNELS` | لیست JSON کانال‌ها | ❌ اختیاری |

سکرت `CHANNELS` فقط وقتی لازم است که نخواهید نام کانال‌ها در ریپوی عمومی دیده شود.
اگر آن را بگذارید، بر `config.json` اولویت دارد:

```json
[{"username":"@one","daily_quota":100},{"username":"@two","daily_quota":80}]
```

## ۶. تنظیمات کامل config.json

همه‌ی رفتار پروژه از این یک فایل کنترل می‌شود.

```json
{
  "source_file": "working.txt",

  "channels": [
    {
      "username": "@YourChannelOne",
      "daily_quota": 100,
      "extra_text": ["🔴 عضو کانال ما شوید: @YourChannelOne", "🤝 پشتیبانی: @AdminOne"]
    },
    { "username": "@YourChannelTwo",   "daily_quota": 100 },
    { "username": "@YourChannelThree", "daily_quota": 100 }
  ],

  "schedule": {
    "window_hours": 24,
    "batch_size": 10,
    "grace_minutes": 10,
    "max_messages_per_run": 6,
    "inter_message_delay_seconds": 5,
    "rebuild_when_exhausted": true
  },

  "distribution": { "mode": "round_robin", "shuffle": true, "seed": null },

  "cleaning": {
    "aggressive": false,
    "replace_remark": true,
    "remark_template": "{channel}",
    "strip_ad_params": true,
    "extra_ad_keywords": [],
    "extra_ad_param_names": []
  },

  "cache": { "file": "state/cache.json", "ttl_days": 30, "max_entries": 200000 },

  "message": {
    "header": "🌐 <b>V2Ray Configs</b> — {date}\n📦 Batch {batch_index}/{batch_total} • {count} configs\n",
    "footer": "\n🔗 {channel}",
    "extra_text": ["📢 کانال اصلی: {channel}", "🚀 هر روز کانفیگ‌های تازه"],
    "code_block": true,
    "max_chars": 4000
  },

  "runtime": { "dry_run": false, "log_level": "INFO", "state_dir": "state" }
}
```

### channels

| کلید | معنا |
|---|---|
| `username` | یوزرنیم کانال با `@`. آیدی عددی (`-1001234567890`) هم قبول است. |
| `daily_quota` | حداکثر تعداد کانفیگ برای این کانال در هر بازه. سقف است، نه تعداد ثابت. |

تعداد کانال محدودیتی ندارد — ۲ تا، ۳ تا، ۱۰ تا. اسکریپت خودش تقسیم می‌کند.
اگر یکی از کانال‌ها سهمیه‌ی کمتری داشته باشد، بقیه‌ی کانفیگ‌ها بین کانال‌های دیگر پخش می‌شود.

### schedule

| کلید | پیش‌فرض | معنا |
|---|---|---|
| `window_hours` | `24` | کل کانفیگ‌های یک کانال در این بازه پخش می‌شوند. `12` = دو برابر سریع‌تر. |
| `batch_size` | `10` | چند کانفیگ در هر پیام. `1` = هر کانفیگ یک پیام جدا. |
| `grace_minutes` | `10` | کرون گیت‌هاب معمولاً چند دقیقه تأخیر دارد؛ این مقدار آن تأخیر را جبران می‌کند. |
| `max_messages_per_run` | `6` | سقف پیام در هر ران. جلوی سیل پیام بعد از یک وقفه‌ی طولانی را می‌گیرد. `0` = بی‌نهایت. |
| `inter_message_delay_seconds` | `5` | فاصله بین دو پیام پشت‌سرهم. برای دوری از محدودیت نرخ تلگرام. |
| `rebuild_when_exhausted` | `true` | وقتی همه‌ی دسته‌های بازه ارسال شد، بلافاصله نقشه‌ی جدید بساز (به‌جای انتظار تا پایان بازه). |

### distribution

| کلید | مقادیر | معنا |
|---|---|---|
| `mode` | `round_robin` \| `chunk` | `round_robin`: یکی به این کانال، یکی به آن — همه‌ی کانال‌ها ترکیب مشابهی از پروتکل‌ها و سرورها می‌گیرند. `chunk`: هر کانال یک برش پیوسته. |
| `shuffle` | `true` \| `false` | مخلوط کردن + پخش کردن کانفیگ‌های یک سرور تا در یک پیام جمع نشوند. |
| `seed` | `null` یا عدد | عدد ثابت = ترتیب تکرارپذیر (برای تست). `null` = تصادفی. |

### recycle (اختیاری — اگر نگذارید پیش‌فرض‌ها اعمال می‌شوند)

وقتی کانفیگ تازه کمتر از سهمیه باشد، کمبود با کانفیگ‌های قبلاً ارسال‌شده پر می‌شود.
جزئیات کامل در [بخش ۷](#۷-زمانبندی-چطور-کار-میکند).

| کلید | پیش‌فرض | معنا |
|---|---|---|
| `enabled` | `true` | `false` = اگر کانفیگ تازه نبود، هیچ‌چیز ارسال نشود. |
| `cooldown_hours` | `0` | حداقل فاصله تا ارسال دوباره‌ی یک کانفیگ. `0` = بدون محدودیت. |
| `max_times_each` | `0` | حداکثر تعداد ارسال هر کانفیگ در کل. `0` = بی‌نهایت. |

### message

| کلید | معنا |
|---|---|
| `header` | متن بالای پیام. متغیرها: `{date}` `{channel}` `{count}` `{batch_index}` `{batch_total}` |
| `footer` | متن پایانی پیش‌فرض (امضا). همان متغیرها. |
| `extra_text` | متن اضافی دلخواه در انتهای پست (رشته یا لیست آرایه‌ای از خطوط). متغیرها پشتیبانی می‌شوند. |
| `code_block` | `true` = همه‌ی کانفیگ‌ها داخل یک `<pre>` تا با یک تاچ کپی شوند. |
| `max_chars` | سقف کاراکتر هر پیام. حد سخت تلگرام ۴۰۹۶ است؛ اگر دسته بزرگ‌تر شد، خودکار به چند پیام تقسیم می‌شود. |

فرمت هدر، فوتر و `extra_text` **HTML** است (`<b>`، `<i>`، `<code>`، `<a href>`). خود کانفیگ‌ها escape می‌شوند، ولی تگ‌های HTML شما سالم می‌مانند.

### متن اضافی اختصاصی برای هر کانال

می‌توانید `extra_text` را هم به‌صورت عمومی در `message` تعریف کنید و هم به‌صورت اختصاصی برای یک کانال در `channels`:

```json
"channels": [
  {
    "username": "@ChannelOne",
    "daily_quota": 100,
    "extra_text": ["📢 کانال اول", "💬 پشتیبانی: @AdminOne"]
  },
  {
    "username": "@ChannelTwo",
    "daily_quota": 100,
    "extra_text": ""   // این کانال هیچ متن اضافی دریافت نمی‌کند (عمومی هم خاموش می‌شود)
  },
  {
    "username": "@ChannelThree",
    "daily_quota": 100
    // از message.extra_text عمومی استفاده می‌کند
  }
]
```

نکات مهم `extra_text`:

- می‌توانید آن را به‌صورت **یک لیست JSON** بنویسید (مانند بالا) تا نیازی به `\n` زشت در یک رشته‌ی بلند نباشد.
- اگر دسته‌ای خیلی بزرگ باشد و به چند پیام تقسیم شود، `extra_text` **فقط در انتهای پیام آخر** می‌آید تا پست شکل جمع‌بندی داشته باشد و تکرار نشود.
- اگر متغیری ناشناس در آن بنویسید (مثلاً `{custom_word}`)، اسکریپت **کرش نمی‌کند** و آن متن را عینا چاپ می‌کند.

### تغییر تنظیمات با متغیر محیطی

هر کلیدی را می‌توان بدون ویرایش فایل، موقتاً override کرد. پیشوند `V2TG_` و برای
تودرتویی دو زیرخط `__`:

```bash
V2TG_SCHEDULE__BATCH_SIZE=20      python main.py run
V2TG_SCHEDULE__WINDOW_HOURS=12    python main.py plan
V2TG_RUNTIME__DRY_RUN=true        python main.py run
V2TG_CLEANING__AGGRESSIVE=true    python main.py preview
V2TG_RECYCLE__ENABLED=false       python main.py plan
V2TG_RECYCLE__COOLDOWN_HOURS=48   python main.py plan
V2TG_CHANNELS='[{"username":"@x","daily_quota":50}]'  python main.py plan
```

## ۷. زمان‌بندی چطور کار می‌کند

### مثال دقیق: ۱۰۰ کانفیگ در ۲۴ ساعت

با `daily_quota: 100` و `batch_size: 10`:

```
۱۰۰ کانفیگ ÷ ۱۰ در هر پیام = ۱۰ دسته
۲۴ ساعت ÷ ۱۰ دسته = هر ۲ ساعت و ۲۴ دقیقه یک پیام

دسته ۱  →  ساعت 00:00   (فوری، همان ران اول)
دسته ۲  →  ساعت 02:24
دسته ۳  →  ساعت 04:48
دسته ۴  →  ساعت 07:12
دسته ۵  →  ساعت 09:36
دسته ۶  →  ساعت 12:00
دسته ۷  →  ساعت 14:24
دسته ۸  →  ساعت 16:48
دسته ۹  →  ساعت 19:12
دسته ۱۰ →  ساعت 21:36
```

این زمان‌ها در `state/queue.json` نوشته می‌شوند. کرون هر ۱۵ دقیقه بیدار می‌شود و
می‌پرسد «چیزی وقتش رسیده؟» — اگر نه، بدون هیچ کاری تمام می‌شود (چند ثانیه).

### چرا کرون و نه یک ران طولانی؟

GitHub Actions هر job را حداکثر **۶ ساعت** اجرا می‌کند. پس یک ران نمی‌تواند ۲۴ ساعت
بخوابد. راه‌حل: ران‌های کوتاه و مکرر + وضعیت ذخیره‌شده در ریپو. مزایا:

- کرش، کنسل شدن، یا قطع شبکه فقط همان دسته را عقب می‌اندازد.
- دقیقه‌ی Actions تقریباً مصرف نمی‌شود (رانِ بی‌کار ~۲۰ ثانیه است).
- می‌توانید هر لحظه `state/queue.json` را باز کنید و ببینید چه چیزی کِی می‌رود.

### تغییر فاصله‌ی کرون

در `.github/workflows/send.yml`:

```yaml
- cron: "*/15 * * * *"   # هر ۱۵ دقیقه (پیش‌فرض)
- cron: "*/5  * * * *"   # هر ۵ دقیقه — زمان‌بندی دقیق‌تر
- cron: "0    * * * *"   # هر ساعت — کم‌مصرف‌تر
```

قاعده: فاصله‌ی کرون باید **کمتر** از فاصله‌ی دسته‌ها باشد، وگرنه چند دسته با هم
جمع می‌شوند و پشت‌سرهم ارسال می‌شوند.

> کرون گیت‌هاب best-effort است و در ساعات پرترافیک تا ۱۵ دقیقه تأخیر می‌گیرد.
> `grace_minutes` دقیقاً برای همین است.

### بعد از پایان بازه چه می‌شود؟

با `rebuild_when_exhausted: true` (پیش‌فرض) به‌محض ارسال آخرین دسته، `working.txt`
دوباره خوانده می‌شود و نقشه‌ی جدید ساخته می‌شود — با کانفیگ‌هایی که هنوز نرفته‌اند.
اگر `working.txt` را با کانفیگ تازه به‌روز کنید، خودکار وارد چرخه می‌شوند.

### اگر کانفیگ تازه‌ای نیامد؟ (چرخش خودکار)

اگر تعداد کانفیگ‌های تازه کمتر از سهمیه‌ی کل کانال‌ها باشد، اسکریپت **کمبود را با
کانفیگ‌های قبلاً ارسال‌شده پر می‌کند** تا کانال‌ها هرگز سکوت نکنند:

```
سهمیه‌ی کل: ۳۰۰   (۳ کانال × ۱۰۰)
کانفیگ تازه: ۱۱۸
کمبود: ۱۸۲  →  ۱۸۲ کانفیگ قدیمی بازچرخانی می‌شود، «قدیمی‌ترین ارسال» اول
```

قواعد چرخش:

- **اولویت همیشه با کانفیگ تازه است.** فقط کمبود پر می‌شود، نه بیشتر.
- **ترتیب: قدیمی‌ترین ارسال اول.** هر کانفیگ زمان آخرین ارسالش (`last`) در کش
  ذخیره می‌شود، پس چرخش کل مخزن را به‌ترتیب طی می‌کند و چند کانفیگ ثابت تکرار نمی‌شوند.
- **هیچ کانفیگی در یک بازه به دو کانال نمی‌رود**، حتی در حالت بازچرخانی.
- **کانفیگ باید هنوز در `working.txt` باشد.** چیزی که از فایل منبع حذف شده، بازنمی‌گردد.

تنظیمات اختیاری (اگر کلید `recycle` را در `config.json` نگذارید، پیش‌فرض‌ها اعمال می‌شوند):

```json
"recycle": {
  "enabled": true,
  "cooldown_hours": 0,
  "max_times_each": 0
}
```

| کلید | پیش‌فرض | معنا |
|---|---|---|
| `enabled` | `true` | `false` = رفتار قبلی؛ اگر کانفیگ تازه نبود، هیچ‌چیز ارسال نمی‌شود. |
| `cooldown_hours` | `0` | حداقل فاصله‌ی زمانی تا ارسال دوباره‌ی یک کانفیگ. `48` = هر کانفیگ حداقل دو روز استراحت کند. `0` = بدون محدودیت. |
| `max_times_each` | `0` | حداکثر تعداد ارسال هر کانفیگ در کل عمر پروژه. `3` = هر کانفیگ بیشتر از ۳ بار نرود. `0` = بی‌نهایت. |

در لاگ و در Summary هر ران، تعداد بازچرخانی‌شده‌ها گزارش می‌شود:

```
only 118 fresh config(s) for a quota of 300 — recycling 182 previously sent config(s), oldest first
total configs: 300, pending batches: 30 (182 recycled)
```

## ۸. حافظه کش ضدتکرار

### چطور «تکراری» تشخیص داده می‌شود

مقایسه‌ی متن خام کافی نیست — یک سرور می‌تواند با ده remark مختلف و ترتیب پارامتر
متفاوت ظاهر شود. به‌جای آن، برای هر کانفیگ یک **اثر انگشت معنایی** ساخته می‌شود:

| در اثر انگشت **هست** | در اثر انگشت **نیست** |
|---|---|
| پروتکل، آدرس سرور، پورت | remark / نام کانال |
| UUID یا رمز | `fp` (chrome/firefox/…) |
| نوع transport و security | `allowInsecure` و `insecure` |
| `sni`، `host`، `path`، `pbk`، `sid` | ترتیب پارامترها |
| | متن‌های تبلیغاتی |

نتیجه: این دو **یکی** شمرده می‌شوند —

```
vless://uuid@1.2.3.4:443?type=tcp&security=reality&fp=chrome#🔥Join:@AdOne
vless://uuid@1.2.3.4:443?security=reality&type=tcp&fp=firefox#@AdTwo
```

### فایل کش

`state/cache.json` بعد از هر ارسال کامیت می‌شود، پس بین ران‌ها باقی می‌ماند:

```json
{
  "version": 1,
  "updated_at": 1786000000,
  "count": 155,
  "entries": {
    "a3f9c2...": {
      "ts": 1786000000,      // اولین ارسال
      "last": 1786200000,    // آخرین ارسال (مبنای ترتیب چرخش)
      "channel": "yourchannelone",
      "hits": 2              // چند بار ارسال شده
    }
  }
}
```

| کلید تنظیم | معنا |
|---|---|
| `ttl_days` | بعد از این تعداد روز، اثر انگشت فراموش می‌شود و آن کانفیگ به‌عنوان «تازه» شمرده می‌شود. `0` = هرگز فراموش نکن. |
| `max_entries` | سقف تعداد رکورد. وقتی پر شد، قدیمی‌ترین‌ها حذف می‌شوند. |

با `ttl_days: 30` و ۱۵۰ کانفیگ در روز، حجم فایل حدود چند صد کیلوبایت می‌ماند — بی‌مسئله.

### تضمین «به هیچ کانالی نرو»

کش **مشترک بین همه‌ی کانال‌ها** است. تقسیم‌کننده هم هر کانفیگ را فقط به یک کانال
می‌دهد. پس یک کانفیگ حتی در یک بازه هم به دو کانال نمی‌رود.

### پاک کردن کش

```bash
python main.py clear-cache --yes    # همه‌ی کانفیگ‌ها می‌توانند دوباره بروند
```

بدون `--yes` اجرا نمی‌شود؛ این عمل برگشت‌ناپذیر است.

## ۹. تمیزکاری تبلیغات

تبلیغ‌کننده‌ها یوزرنیم خود را در سه جای مختلف کانفیگ تزریق می‌کنند:

**۱. در remark (بعد از `#`)** — همیشه با نام کانال شما جایگزین می‌شود:

```
پیش:  ...&sni=x.com#🔥Join+Telegram:@Farah_VPN🟣
پس:   ...&sni=x.com#@YourChannel
```

**۲. به‌عنوان یک پارامتر جعلی** — کامل حذف می‌شود:

```
پیش:  ?Telegram=@GozargahAzad,@GozargahAzad,@GozargahAzad&security=reality
پس:   ?security=reality
```

**۳. داخل `host` / `path` / `sni` که پارامترهای واقعی‌اند** — اینجا باید احتیاط کرد.

### حالت هوشمند (پیش‌فرض: `aggressive: false`)

قاعده: **هیچ‌وقت کانفیگ سالم را خراب نکن.**

| ورودی | خروجی | چرا |
|---|---|---|
| `host=play.google.com` | دست‌نخورده | هاست‌نیم معتبر است |
| `host=BIA_TELEGRAM?=@ShadowFlux2---@ShadowFlux2` | پارامتر حذف می‌شود | فقط تبلیغ است، ارزش عملکردی ندارد |
| `host=@AdChannel---cdn.real-site.com---@AdChannel` | `host=cdn.real-site.com` | هاست واقعی نجات داده می‌شود |
| `path=/api/v1/rooms/633/sync/?TELEGRAM-MARAMBASHI?ed` | `path=/api/v1/rooms/633/sync/?ed` | مسیر واقعی حفظ، تبلیغ بریده |
| `path=/?ed=2082` | دست‌نخورده | `ed=` یک hint واقعی early-data است |
| `path=/Join-Javidnaman-on-Telegram` | دست‌نخورده | تک‌بخشی و بدون ساختار → احتمالاً مسیر واقعی سرور همین است |
| `f\`p\`=firefox` | حذف | نام پارامتر خراب است، هیچ کلاینتی نمی‌خواندش |
| `extra={` | حذف | JSON بریده، کلاینت را به خطا می‌اندازد |

روی `working.txt` نمونه (۱۷۰ خط) نتیجه: ۱۴ پارامتر `host` تبلیغاتی حذف، ۷ `extra` خراب حذف،
۲ پارامتر `Telegram=` حذف، ۱ نام پارامتر خراب حذف، و ۱ `sni` و ۱ `path` اصلاح شدند —
بدون از دست رفتن هیچ کانفیگ سالمی.

### حالت تهاجمی (`aggressive: true`)

هر `@username` و هر کلمه‌ی تبلیغاتی، هر جا که باشد، حذف می‌شود — حتی اگر داخل
`path` واقعی باشد. تبلیغ صفر، اما احتمال از کار افتادن بعضی کانفیگ‌ها وجود دارد.

```bash
V2TG_CLEANING__AGGRESSIVE=true python main.py preview   # اول ببینید چه می‌شود
```

### افزودن الگوی دلخواه

```json
"cleaning": {
  "extra_ad_keywords": ["myrival", "freevpn2026"],
  "extra_ad_param_names": ["promo", "ads", "sponsor"]
}
```

`extra_ad_param_names` پارامترهایی است که فقط با دیدن نامشان حذف می‌شوند.

### تغییر قالب remark

```json
"remark_template": "{channel}"                 →  @YourChannel
"remark_template": "🚀 {channel}"              →  🚀 @YourChannel
"remark_template": "{channel} | Free V2Ray"    →  @YourChannel | Free V2Ray
```

## ۱۴. عیب‌یابی

### `missing credentials: TELEGRAM_SESSION`

سکرت‌ها ثبت نشده‌اند یا نامشان اشتباه است. در **Settings → Secrets and variables →
Actions** بررسی کنید که هر سه سکرت با همین نام‌های دقیق وجود دارند.

### `TELEGRAM_SESSION is not authorized`

رشته‌ی session باطل شده — معمولاً چون در تلگرام سشن‌ها را terminate کرده‌اید یا رمز
اکانت را عوض کرده‌اید. یک رشته‌ی جدید بسازید:

```bash
python tools/gen_session.py
```

و مقدار سکرت را به‌روز کنید.

### `cannot resolve @YourChannel`

سه دلیل ممکن:

1. یوزرنیم غلط تایپ شده است.
2. اکانتِ session عضو کانال نیست. **باید عضو باشد** — حتی برای کانال عمومی، تلگرام
   اجازه‌ی ارسال به کانالی که در آن نیستید نمی‌دهد.
3. کانال خصوصی است — در این حالت به‌جای یوزرنیم، آیدی عددی بگذارید:
   `{"username": "-1001234567890", "daily_quota": 100}`

### `the session account cannot post in @Channel`

اکانت عضو است ولی دسترسی ارسال ندارد. در کانال: **Administrators → Add Admin** و
حداقل **Post Messages** را فعال کنید.

### `flood wait: sleeping 30s`

تلگرام موقتاً محدود کرده است. اسکریپت خودش صبر می‌کند و دوباره تلاش می‌کند. اگر
تکرار شد، فاصله‌ها را باز کنید:

```json
"inter_message_delay_seconds": 15,
"max_messages_per_run": 3
```

### هیچ چیز ارسال نمی‌شود، لاگ می‌گوید «nothing is due yet»

طبیعی است — یعنی وقت دسته‌ی بعدی نرسیده. زمان دسته‌ی بعد در همان لاگ نوشته شده.
برای ارسال فوری: **Run workflow** با `rebuild=true`.

### لاگ می‌گوید «nothing to schedule»

با چرخش خودکار (`recycle.enabled: true`) این پیام تقریباً هرگز نباید ظاهر شود. اگر دیدید،
یعنی `working.txt` هیچ کانفیگ **معتبری** ندارد (فایل خالی است یا همه‌ی خطوط خراب‌اند). با
لاگ کامل بررسی کنید:

```bash
python main.py plan --log-level DEBUG
```

اگر چرخش را خودتان خاموش کرده باشید (`"enabled": false`)، این پیام یعنی همه‌ی
کانفیگ‌ها قبلاً ارسال شده‌اند؛ آن‌وقت یا `working.txt` را به‌روز کنید، یا کش را پاک کنید:

```bash
python main.py clear-cache --yes
```

### یک کانفیگ برای بار دوم ارسال شد

اگر مخزن کانفیگ‌های تازه تمام شود، این **رفتار خواسته‌شده** است: چرخش خودکار جای
سکوت کانال را می‌گیرد. برای کنترل آن:

```json
"recycle": { "enabled": true, "cooldown_hours": 48, "max_times_each": 3 }
```

یعنی هر کانفیگ حداقل دو روز فاصله داشته باشد و در کل عمر پروژه بیش از ۳ بار ارسال نشود.
برای خاموش کردن کامل: `"enabled": false`.

### تعداد کانفیگ‌ها کمتر از انتظار است

`plan` را با لاگ کامل اجرا کنید تا دلیل حذف هر خط را ببینید:

```bash
python main.py plan --log-level DEBUG
```

روی فایل نمونه، ۱۷۰ خط ورودی به ۱۵۵ کانفیگ آماده رسید: ۱۵ مورد تکراری معنایی بودند
(همان سرور با remark متفاوت).

### ورک‌فلو نمی‌تواند state را پوش کند

مطمئن شوید در **Settings → Actions → General → Workflow permissions** گزینه‌ی
**Read and write permissions** فعال است.

### دو ران هم‌زمان اجرا شدند

نباید بشود — `concurrency` در ورک‌فلو جلوی آن را می‌گیرد. اگر باز هم دیدید،
بررسی کنید که بلوک `concurrency` در `send.yml` حذف نشده باشد.

## ۱۵. نکات امنیتی

- **`session string` معادل رمز اکانت است.** فقط در GitHub Secrets. هرگز در کد،
  کامیت، ایشو یا اسکرین‌شات.
- **`.gitignore` فایل‌های `*.session` و `.env` را مسدود می‌کند.** آن خطوط را حذف نکنید.
- **ریپوی عمومی:** `working.txt`، `config.json` و نام کانال‌ها برای همه قابل دیدن است.
  سکرت‌ها هرگز در لاگ Actions نمایش داده نمی‌شوند (گیت‌هاب خودکار ماسک می‌کند). اگر
  نمی‌خواهید نام کانال‌ها دیده شود، از سکرت `CHANNELS` استفاده کنید.
- **پیشنهاد:** برای این کار از یک اکانت تلگرام جداگانه (شماره‌ی دوم) استفاده کنید،
  نه اکانت شخصی اصلی‌تان.
- **اگر سشن لو رفت:** تلگرام → **Settings → Devices → Terminate all other sessions**،
  بعد یک session جدید بسازید و سکرت را به‌روز کنید.

## ۱۶. سوالات متداول

**می‌توانم تعداد کانال‌ها را عوض کنم؟**
بله. `channels` را در `config.json` کم یا زیاد کنید. اسکریپت خودش دوباره تقسیم می‌کند.
بهتر است بعد از تغییر، یک‌بار `rebuild=true` اجرا کنید.

**می‌شود هر کانال سهمیه‌ی متفاوت داشته باشد؟**
بله: `[{"username":"@a","daily_quota":150},{"username":"@b","daily_quota":50}]`

**می‌شود کانفیگ‌ها را در ۱۲ ساعت بفرستم نه ۲۴؟**
`"window_hours": 12`.

**هر کانفیگ در یک پیام جدا؟**
`"batch_size": 1`. توجه: با ۱۰۰ کانفیگ می‌شود ۱۰۰ پیام در روز.

**اگر `working.txt` را وسط بازه به‌روز کنم؟**
نقشه‌ی فعلی دست‌نخورده ادامه می‌دهد. کانفیگ‌های تازه در بازه‌ی بعدی وارد می‌شوند. برای
ورود فوری: **Run workflow** با `rebuild=true`.

**اگر دیگر کانفیگ تازه‌ای نیاید، کانال‌ها خالی می‌مانند؟**
نه. چرخش خودکار کمبود را با کانفیگ‌های قبلاً ارسال‌شده پر می‌کند، به‌ترتیب
قدیمی‌ترین ارسال. بخش [«اگر کانفیگ تازه‌ای نیامد»](#۷-زمانبندی-چطور-کار-میکند) را ببینید.

**چطور جلوی تکرار زودهنگام یک کانفیگ را بگیرم؟**
`"recycle": { "cooldown_hours": 48 }` — هر کانفیگ حداقل دو روز فاصله می‌گیرد.

**آیا با بات‌توکن هم کار می‌کند؟**
این نسخه با اکانت کاربر (StringSession) کار می‌کند چون درخواست همین بود. Telethon از
بات هم پشتیبانی می‌کند؛ برای آن باید در `sender/tg.py` از `bot_token` استفاده شود.

**چند دقیقه Actions مصرف می‌کند؟**
رانِ بی‌کار حدود ۲۰–۳۰ ثانیه است. با کرون ۱۵ دقیقه‌ای، روزانه حدود ۹۶ ران ≈ ۴۰ دقیقه.
ریپوی عمومی سهمیه‌ی نامحدود دارد؛ ریپوی خصوصی ماهی ۲۰۰۰ دقیقه رایگان دارد.

**پروتکل‌های پشتیبانی‌شده؟**
`vless` `vmess` `trojan` `ss` `ssr` `hysteria` `hysteria2` `hy2` `tuic` `socks`
`wireguard` `anytls` `mieru`. فایل نمونه شامل vless، vmess، trojan و ss است.

**کانفیگ‌های خیلی طولانی چه می‌شوند؟**
اگر یک کانفیگ تنها از سقف یک پیام بزرگ‌تر باشد حذف می‌شود (در لاگ به‌عنوان
`oversized` گزارش می‌شود)، چون در هیچ پیامی جا نمی‌شود.
